# Persistent guide service source template

This directory contains the reviewed algorithms for the dedicated guide service. Its public release binding is intentionally unbound: it cannot authorize creation, adoption, start, stop or removal of a container. The older Node launcher is retired.

One private source-verified bootstrap controls one fixed Lyra, Nova or Orion slot per invocation. Ownership comes from an acknowledged immutable ID, complete physical Config/HostConfig and source verification, a private durable pending-operation journal, and current native/browser/controller evidence. Names, labels, image hashes and old journals do not deserialize authority. Docker owns a successful detached browser after the local entry closes. There is no all-profile start, automatic restart, adoption, permissive fallback or mutation retry.

The full container model distinguishes never-started created from invoked running/exited. It preserves the engine's exact lifecycle representation, ordered Env, complete host/resource/security fields, recorded invocation and current player. Immutable rootfs members use bounded TAR reads. Runtime health uses one fixed read-only Node program in the config-checked running container's tmpfs namespace and unchanged renderer/source/controller lease validation. STOP uses the supported exact wire form and requires a complete acknowledgment. Unknown effect or local descriptor/client uncertainty is held.

The production installation is a separately reviewed private directory, with source directories0700 and manifest-checked files0600, under the exact qualified Linux interpreter/profile. Ordinary Git checkout permissions are not an installation; do not relax the verifier. A private source-bound release, actual immutable image/content and current public-body receipts, fresh complete protected baseline, canonical private plan and journal are required. They are not distributed here and must not be committed. Public checks and test fixtures are never production authority.

Complete ownership and current health admission are separate. START requires every applicable peer's original current native/runtime/controller/renderer proof and exact public/native bodies. Status reports each peer independently and invalidates expired or changed observations; a full ownership/history failure or uncertain local client/descriptor aborts before further I/O. STOP requires a conclusive acknowledged ready exact ID with no pending or held failure. It preserves full ownership/source/invocation/protected-isolation checks, can stop a known running target despite an unhealthy sibling, and records an already-exited exact invocation as observed-exited without a STOP syscall or fabricated acknowledgment. The fixed runtime transport is read only after an immediate full running inspection outside degraded-health handling.

The browser image requires the explicit command `node runner.mjs --renderer-mode=canvas` supplied by that service. Its source can be inspected and tested without launching Docker or a browser. Bare npm start, the old CLI and an image build alone are not deployment paths. A rebuilt image is a new candidate until its actual complete content and runtime behavior are separately qualified.

Visitor interaction uses the avatar menu's **Talk to Nearby Guides** panel, an actual nearby guide selection, and zodiac text or buttons. Supported targeted `WA` events carry commands and replies. Dedicated bots disable their own proximity-meeting participation with `disablePlayerProximityMeeting`; there is no native bubble-chat fallback. The core app, iframe SDK and normal human proximity meetings are unchanged. These are source-interface requirements; live interaction acceptance remains separate.

Public tests use clearly marked synthetic identities and evidence. The original private physical-observation tests remain separately retained with their qualification receipts. A public-source test pass does not prove current attendees, shared replies or prolonged runtime reliability. Report those outcomes only from current actual acceptance evidence.
