# Stationary Roadster display

The entrance plaza contains a silver angular Roadster-inspired car above the replaceable Atlas sponsor panel. It rests, ignites white/cyan jets, rises, hovers, jumps through a full roll, descends and lands over one fixed pad. The display uses the existing native Tiled animated-tile pipeline; it adds no visitor script, bot behavior, travel, interaction, collision or WAM metadata.

The 160×160 frame sits at tile(73,60), spanning five tiles each way. Its visible pixels fit the conservative arrival camera band; transparent right padding extends beyond that band for the left spawn column. The chosen space is visibly blue reception terrace, with no overlap with props, sponsor panels, entries, exits, WAM areas or any of the 743 audited guide cells. An older underlying terrain rectangle describes the main avenue, but its visible terrain is covered by the reception terrace here. The root visual review accepted this placement.

The cycle is 12.8seconds: landed 3s, ignition 0.6s, rise 0.5s, low hover 0.7s, hover 1.2s, jump 0.5s, six roll poses 0.35s each, recovery 0.5s, descend 0.8s, touchdown 0.6s and rest 2.3s. First and final poses are grounded with the same anchor; they are separate generated drawings, not identical pixels. Each pose stays horizontally centered over the pad. Cold-gas jets are stylized animation, not a technical simulation of a real vehicle.

`art/source/roadster-poses.png` is the original generated image (SHA-256 `08b8e46661d57bb4f44ea0e09bdee91debc3311440d1d2406a949e164bd86cd0`). It is actually 1254×1254, despite the generation prompt requesting 1024×1024. The full prompt and authoring parameters are retained in `roadster-authoring.json`. Private photographs were visual references only and are not distributed. No sponsor logo is baked into the display.

Compile the art with `node tools/run-tool.mjs tools/art/roadster.ts`. The compiler divides the source at 0,313,627,940,1254, finds each pose's alpha bounds, applies one 0.4 nearest-neighbor scale, thresholds alpha to 0/255, centers it at integer coordinates and packs native 32px tiles with 25 synchronized carrier animations. `art/source/roadster.json` records each source crop, target rectangle, timing and exact inputs. The generated atlas remains below the existing 4MiB decoded-image bound.

The compiler writes only the atlas and metadata. When deliberately revising an animation, copy its exact `overlay` descriptor into the overworld layout and apply the corresponding tileset/layer to the native TMJ; preserve existing layer IDs/GIDs and fields. The first addition appended one layer/tileset and incremented only `nextlayerid`; the inverse is tested against the c638 semantic receipt. Refresh previews with `npm run maps:build`, then run `npm run art:check`, the Roadster/native map/guide tests, `npm run buildmap` and the source checker. Do not refreeze the original 303 inventory or alter unrelated revision entries.

The guide map guard includes decorative geometry. This display therefore requires a re-audited geometry receipt and a newly built module pin; guide cells, routes, controller behavior and guard enforcement are unchanged. The module/config pins must move together. Existing c638 deployed browsers are not evidence that this new map/module pair works live. Actual live animation and the new guide startup remain coordinator acceptance gates; local evidence uses Tiled 1.12.2 and the checksum-pinned deployed Phaser parser for every pose and loop boundary.
