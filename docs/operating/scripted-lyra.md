# Scripted shared guides

Lyra, Nova and Orion are authored walking guides for the frozen overworld, using one shared module and separate dedicated browsers. The dedicated release artifact is `dist/bots/lyra.js`; release verification must confirm its self-contained module closure before controller bytes are bound to an image or service. It exports `default.run(metadata)` following the [official starter](https://github.com/workadventure/bot-starter-kit/blob/master/src/main.ts). Importing it is safe without `WA`; calling `run` requires the initialized WorkAdventure scripting iframe of the dedicated bot browser. Regular map visitors never import or start this controller.

Build and verify with:

```sh
npx vitest run tests/lyra-bot.test.ts tests/lyra-bot-personas.test.ts tests/lyra-bot-release.test.ts --maxWorkers=1 --testTimeout=30000
npm run buildmap
node publication/verify-source.mjs
shasum -a 256 dist/bots/lyra.js
```

Publication and activation are separate steps. The stable public destination is `https://htooayelwinict.github.io/varcamp-map/bots/lyra.js`. Before activating any release, verify successful full canonical CI and Pages deployment, then compare the exact HTTPS module bytes with the reviewed artifact. A separately reviewed private service installation must establish current status from its exact owned IDs and journal; the public unbound template cannot authorize activation. A build alone is not live acceptance. After those checks, test that two independent visitor sessions observe exactly three distinct moving guides and shared replies. Source tests and a local build do not establish live acceptance.

## Talk to a nearby guide

Open the avatar menu at the top right, choose **All settings**, then choose **Talk to Nearby Guides** from the menu list. Choose an actual guide listed in the panel, then type a zodiac name or press a zodiac button. The fixed guide identities are `Lyra[BOT]`, `Nova[BOT]` and `Orion[BOT]`; use the panel's current nearby list rather than assuming all three are present. Replies appear in this panel. Native bubble chat is not a command or reply channel for the guides, and there is no native-chat fallback.

All twelve zodiac names work, including `Gemini`, `Cancer` and `Libra`. The selected guide also accepts `help`, `rooms`, `go <destination>` and `stop`; Burmese forms are `အကူအညီ`, `အခန်းများ`, `သွား <destination>` and `ရပ်`. Known destination names work directly. Speaker rooms accept numbers 1–12 and Burmese digits. Commands ignore English case and repeated whitespace. Burmese command forms receive Burmese replies. Unsupported text receives the short help response, with the existing per-visitor reply cooldown. Choose the intended guide in the panel before sending a command; `stop` applies to the sender's escort with that selected guide.

Speaker rooms are Aries, Taurus, Gemini, Cancer, Leo, Virgo, Libra, Scorpio, Sagittarius, Capricorn, Aquarius and Pisces. Other destinations are Solar Hall, Lunar Hall, Mazes, Park, Harbor and Exploration. Lyra explains the onward gate and stops at the audited waypoint before its portal. The first requesting visitor owns the escort until home; another visitor receives a busy response. Visitors keep control of their movement and can leave at any time. An already pending native movement step settles before a changed command takes effect.

The panel and dedicated bot controller use supported targeted `WA` events for commands and replies. Dedicated bots call the official `disablePlayerProximityMeeting` API for their own proximity-meeting participation, removing their dependency on the native chat timeline. This does not change normal human proximity meetings, the core app or the iframe SDK. The guide controller does not subscribe to native bubble chat as an alternative transport.

The module accepts `default.run({ persona: 'lyra' })`, `default.run({ persona: 'nova' })`, or `default.run({ persona: 'orion' })`. Missing persona metadata defaults to Lyra, including official metadata without that field. An explicitly invalid persona fails. The public player ID/name, read after `WA.onInit`, must match the chosen fixed identity: `Lyra[BOT]`, `Nova[BOT]`, or `Orion[BOT]`. Metadata cannot override names, routes or URLs.

## Movement and diagnostics

The module uses only the 743 audited normal cells in `src/bots/lyra-routes.json`. The four native welcome spawns have one initial exception: walk straight north on the original spawn column to row 64, then use the normal graph. Fixed homes are Lyra tile `(70,70)` / pixel `(2256,2256)`, Nova `(73,73)` / `(2352,2352)`, and Orion `(66,70)` / `(2128,2256)`. Their patrols rotate the same existing audited corners; neither the graph nor startup exception expands. Every native movement targets one adjacent tile center, followed by a 100 ms pause. Normal movement can never reenter a reserved startup cell.

A Web Crypto SHA-256 guard checks native dimensions, layers and embedded tileset definitions before movement. Source and release maps have the same signature: the map script property and tileset image URLs are excluded. Runtime objectgroup `class` aliases are normalized only when they exactly duplicate an existing nonempty `type`, as confirmed by the full live raw-versus-runtime map audit. Contradictory classes, class-only objects, tile-layer metadata, coordinates, collision definitions and exits remain signature-bearing. Provenance pins the audited source hashes, original proposal hash and allowed-cell digest. Geometry changes require a new audit, updated provenance and independent route verification; do not weaken the guard to make an incompatible map run.

Watch the dedicated browser console for `VARCAMP_GUIDE_TERMINAL` structured records, with a human-readable stop summary and the original error evidence. A failed/cancelled move, wrong result cell, unexpected player position, changed room, incompatible map, ten-second movement timeout or sixty-second startup timeout stops all future actions. A timed-out movement remains quarantined until its native promise settles. Repeated `run` calls stop the prior controller and wait for its pending API work; they cannot stack movement loops. Closing the dedicated browser stops its session. Page lifecycle cleanup removes owned subscriptions and timers. An already-issued native move may finish after cleanup, but no later step is issued.
